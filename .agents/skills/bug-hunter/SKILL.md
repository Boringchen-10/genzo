# 缺陷排查与修复

当用户报告异常行为、错误日志、崩溃、测试失败或回归问题时使用本技能。新功能从零开发使用 `project-builder`；不以缺陷为目标的常规维护使用 `project-maintainer`。

## 工作流程

1. 阅读仓库根目录的 `AGENTS.md` 和与问题有关的项目文档；检查项目结构、工作区修改、相关代码路径和已有测试。
2. 整理预期行为、实际行为、错误信息、触发条件和影响范围。区分已知事实与假设；必要时向用户索取缺失且无法从仓库或日志确认的信息，同时继续进行不依赖该信息的检查。
3. 尽可能在隔离、可重复的条件下复现问题。优先使用现有测试或安全的临时夹具，不读写用户真实数据或媒体文件。
4. 沿调用链定位根因，检查边界条件、错误处理和相关回归；不要只隐藏报错或扩大改动来绕开问题。
5. 实施最小且针对根因的修改，并增加或调整能覆盖故障及其关键边界的回归检查。
6. 运行相关测试、静态检查或构建。若检查无法运行或失败，记录具体结果，不将其描述为通过。
7. 汇报复现方式、根因、修改内容和验证证据；明确残留风险或未验证部分。

## 安全边界

- 不未经确认删除重要文件、覆盖用户数据、修改真实媒体文件，或运行会丢弃未提交更改的 Git 命令。
- 保留与缺陷无关的现有工作区修改；不顺带重构无关模块。
- 如果无法复现，说明已检查的路径和剩余不确定性，不把猜测当作根因。
