# 项目长期维护

当用户要求整理、优化或持续维护现有项目，且任务并非以定位单个 Bug 或从头开发新项目为主时使用本技能。明确缺陷优先使用 `bug-hunter`；完整新功能优先使用 `project-builder`。

## 工作流程

1. 阅读仓库根目录的 `AGENTS.md` 及相关架构、路线和设计文档。检查项目结构、当前依赖与版本、工作区修改、已有质量检查和兼容性要求。
2. 把维护目标限定为具体问题，例如重复代码、性能瓶颈、依赖风险、死代码、平台兼容或文档过期。先收集证据，再决定是否修改。
3. 复杂或跨模块维护先给出计划和验收条件。优先采用渐进式、可审阅的修改，保持现有行为与数据格式兼容。
4. 重构前确认行为边界并保留回归覆盖；性能优化应说明瓶颈证据和预期影响；依赖调整应检查必要性、许可证、版本影响和替代方案。
5. 清理代码前确认目标确实未使用；未经用户确认，不删除重要文件或数据，不覆盖用户内容，不执行破坏工作区的 Git 操作。
6. 同步维护受本次变化影响的说明、配置示例、迁移或兼容性文档；不把未实现的路线图设想当作当前要求。
7. 运行可用的相关测试、静态检查、构建或兼容性检查，并如实汇报通过、失败、跳过的项目及原因。

## 完成标准

- 维护目标有证据支撑，改动与目标相称。
- 现有功能、用户数据和兼容性边界得到保留。
- 相关检查结果可复核，文档与当前实现一致。
