# Genzo 个人同步协议 V1

状态：2026-10-04 确认的实现契约。Windows 与 Android 使用同一个 Rust 核心和夹具；本文不代表安卓联调已经通过。

## 范围与隔离

一个人、一个资料库、多台设备。每台设备独立 SQLite；服务器只交换资料。首版同步动漫、电影、电视剧（现有 `works.type=video`），保留 Windows 书架等既有功能但不同步其记录。

同步：标题、原名、简介、年份、公开图片 URL、公共来源 ID、字段来源、人工字段锁定、收藏、标签、个人评分、笔记、状态、公共分集资料、分集观看状态、观看会话和播放位置。

设备独有：作品/文件本地 ID 与对应表、文件路径和 SAF URI、目录、来源认证、文件访问授权、播放器、缓存、数据库、设备绑定。凭据由宿主安全存储提供，不能写入载荷或日志。下载图片缓存不参与同步；本地手动图片不能作为路径上传。媒体正文不上传。

## 远端布局

用户填写专用同步目录的 HTTPS URL（禁止账号密码、查询参数或片段）。该目录代表一个资料库，不自动发现或遍历其他资料库。

```text
用户指定目录/
  state.json                   # 唯一权威文档，强 ETag 条件写入
  probe-<随机 UUID>.json        # 能力测试临时文件，测试后删除
```

`state.json` 为 UTF-8 JSON，结构见 `sync-v1/interfaces.ts` 和 `sync-v1/fixtures/`。顶层 `protocolVersion=1`、`libraryId` UUID、`revision` 非负整数、`operations` 按操作 ID 排序的对象。V1 保留全部操作及删除记录，不自行压缩历史。16 MiB 文档上限，达到上限停止上传并提示，不能丢弃历史。资料量增长后的快照/压缩必须另行升级协议。

## 身份

资料库 UUID 在创建空间时产生；加入时必须读取远端 UUID，不能以本机空库替代。设备 UUID 在本机首次参与时生成并持久保存，不能随程序重启重建。复制设备数据库到另一设备须重新注册设备，不能同时使用相同设备 ID。

作品实体为 `work/<UUID>`。本地原有作品 ID 保留，以设备绑定表映射共享实体。公共主锚点 `anchor` 首次确定后不可自动改写：`bangumi/<动画 subject ID>`、`tmdb/movie/<ID>`、`tmdb/tv/<ID>/season/<季号>`。Bangumi 只接受现有影视作品上已确认的主源。补充来源 ID 不自动成为主锚点。同一强锚点的独立实体在读取视图中归为一组，组名取字典序最小实体，原操作 ID 不重写；标题相同不合并。无锚点保持独立，人工确认来源后允许首次绑定；已绑定主锚点被改认时报告身份冲突，不能静默将历史进度迁移到别的作品。

分集键为共享作品组 + 公共来源 + 公共 episode ID；不能仅靠第几集跨源关联。电影使用 `movie` 分集键。媒体版本键 `sha256:<64 位小写十六进制>:<字节数>` 使用完整文件 SHA-256，现有扫描的采样指纹不足以确认同一剪辑。手动确认的版本绑定可使用 `manual:<UUID>`，只在用户明确确认两端对应时复用。同版本还须同分集，且本机时长与记录时长差不超过 2 秒，才应用续播。未确认版本仍可同步观看状态与会话，续播需明确提示待绑定。

## 操作与合并

操作不可变，ID 是 `<deviceId>:<counter>`，counter 为持久单调递增整数；`context` 是操作发生时本机已经看到的各设备最大 counter。每条操作包含实体、字段、JSON 值、观察时间，以及 `origin`（manual / metadata，省略时为 manual）。时间仅展示，不作因果判断。若同 ID 出现不同内容，拒绝整个载荷；不得覆盖。评分数值 `8` 与 `8.0` 语义相同，不因 JSON 数字写法不同误报篡改；实际数值变化仍拒绝。

每个字段为因果多值寄存器。B.context[A.deviceId] >= A.counter 表示 B 看过 A，B 取代 A；同时发生的不同字段独立合并。并发同字段保留所有未被后续操作取代的候选，以 `(counter, deviceId)` 排序选定可重复的显示值。笔记冲突必须显示双方完整内容，用户选一份或合写后发布一个看过双方的操作。其他并发字段也可以由冲突接口查看/选择，不能按电脑时间或服务器到达顺序决定。

字段白名单：`title`、`originalTitle`、`description`、`year`、`coverUrl`、`bannerUrl`、`status`、`favorite`、`rating`、`notes`、`anchor`、`id.<provider>`、`lock.<field>`、`source.<field>`、`tag.<名称>`、`episode.<provider>/<ID>`、`watched.<分集键>`、`session.<UUID>`、`deleted`。嵌套值按对应类型校验；拒绝未知字段和设备私有路径。单个字段最大 256 KiB。

标签键按 SQLite NOCASE 的 ASCII 小写归一，按每个名字的布尔操作合并，移除标签不影响其他设备新增的不同标签。人工锁定字段优先保留人工来源的值，自动刮削不得覆盖已锁定人工资料；解锁是独立操作。

观看会话独立 UUID，保存 episodeKey、versionKey（允许 null）、startedAt、observedAt、positionMs、durationMs、completed、ended。每次真正采集到有效位置才记录；打开文件不算观看。每个会话按字段寄存器规则更新，保留所有会话，倒退/重看合法，不能只取最大的播放位置。不同设备的并发会话保留双方，续播选择最近观察的会话并标明来源；设备时间不可信时可人工选定。已观看与续播分开，已看标记不意味着每个版本都存在可用续播时间。

## 删除与离线

`deleted=true` 是永久删除记录，优先于同实体/同主锚点的普通操作，V1 不提供复活操作。再次收藏已删作品需创建明确的新资料库记录，不能沿用已删除主锚点；恢复需求由后续协议处理。删除只删除资料：媒体文件留在磁盘，本地关联解除；对方路径/目录从未进入载荷。离线源、`media_files.missing` 或撤销文件授权不是资料删除，不产生删除记录。

## 首次加入、持久化与重试

创建：先能力测试；GET 确认 404 后用 `If-None-Match: *` 创建，有竞争则转为读取/合并。加入：必须成功读取并验证 V1 与 libraryId 后才建立本地绑定、合并本地资料；空设备不产生清空远端的操作。

本地业务修改与持久日志在同一 SQLite 事务；日志保存当时因果上下文。待上传操作分配 ID 与日志消费在同一事务。远端应用、绑定、领域投影、因果时钟和抑制回写标志同一事务提交。拉取前先固化本地日志，防止把离线修改误当作看过远端的修改。同步投影不产生新上传日志。

每轮 GET → 合并本地待传 → PUT `If-Match: <强 ETag>`（404 时仅创建模式允许 `If-None-Match: *`）→ GET 验证确实含对应操作 → 本地确认。412 重新读取合并，有限重试后保留待传并提示。上传已成功但响应丢失、断网、重启、认证过期，不删除未确认操作。再次同步以同 ID 重试；重复操作不重复建作品，不循环上传。上传后其他设备的新内容也不能被确认请求覆盖。

## WebDAV 能力与错误

独立探测文件验证认证、PUT/GET/DELETE、强 ETag、正确拒绝过期 `If-Match` 和已存在对象的 `If-None-Match: *`。探测不能写 `state.json`。条件请求不生效或只提供弱 ETag 时拒绝启用；探测残留文件可手工删除。

HTTPS 证书正常验证；禁止重定向以避免认证转发。只有显式测试模式允许 127.0.0.1/localhost/[::1] HTTP。401/403 → `AUTH_REQUIRED`；网络中断 → `OFFLINE`；412 → 重新合并；不支持条件写 → `CONDITION_UNSUPPORTED`；格式/身份不合法 → `INVALID_DOCUMENT`/`IDENTITY_CONFLICT`；新协议 → `PROTOCOL_UNSUPPORTED`，保留本地与远端，旧客户端不能写回；过大 → `LIMIT_EXCEEDED`。日志只记录稳定错误码，不打印凭据或完整 HTTP 响应。

## 共用交付与标准

Rust 核心在 `crates/genzo-sync`；Tauri 命令只是宿主适配。Android 接入同一核心、迁移和夹具，并提供 SAF、Keystore、生命周期和播放器绑定，不能另造同步格式。OpenDesign 接口见 `SYNC_UI_CAPABILITIES.md`。

条件请求依据 [RFC 9110 §13](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests)，目录服务部署依据 [Apache mod_dav](https://httpd.apache.org/docs/2.4/mod/mod_dav.html)。实际阿里云部署须先核对服务器和域名；隔离测试不等于生产验收。
