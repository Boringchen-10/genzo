1. 先确认你是否能直接读取和修改本地工作树：`H:\二次元阅读器\.tmp\android-first`。如果可以，核对该目录的 Git 分支、状态和实际文件；当前开发分支为 `codex/android-first`，基于已发布 Windows v0.5.0。不要改到主目录的 Windows 工作区，也不要另建一套与实际 App 分离的前端。
2. 如果你只能在独立设计环境生成或导出代码，请明确说明。我仍可看你的设计预览并提出修改，你需提供可接入现有 React 工程的源文件或补丁，由 Codex 集成；不能声称已经修改我电脑上的安卓 App。
3. 完整阅读工作树的 `AGENTS.md`、`AI_HANDOFF.md`、`PROJECT_CONTEXT.md`、`ROADMAP.md`、`DESIGN_DIRECTION.md`，以及 `docs/android/FRONTEND_PREVIEW.md`、`CODEX_RESPONSE.md`、`BRIDGE_CONTRACT_V1.md`。再阅读 `design/open-design/android-v1/` 中已有设计规范。以实际代码与最新用户要求为准，旧静态交付不是当前业务实现。

## 当前真实实现

- 技术栈为 Tauri 2 Android WebView + React + TypeScript，后端为 Rust / SQLite。
- 现有可操作页面：首页、媒体库、收藏、我的、来源管理、待整理、作品详情。
- 已接本地目录授权与索引、手动整理、收藏、个人状态 / 评分 / 备注、本地视频播放、稳定媒体ID的观看进度和续播；页面读取真实数据库。
- 候选搜索 / 确认与刷新已经连接接口，完整联网样本闭环仍待验收。
- 当前独立测试APK要重新构建 / 安装才更新React。模拟器热更新尚未验收，不能假设保存文件已自动更新设备。
- 原生播放器为独立LibVLC Activity；当前播放控件仍是验证界面。

## 可修改的前端范围

优先修改：

- `src/android/AndroidApp.tsx`：安卓页面、导航和交互。
- `src/android/mobile.css`：安卓主题Token、布局和组件样式。
- 必要时在 `src/android/` 新增小组件，保持已有编码风格。

继续使用 `src/android/api.ts` 与共享 `src/api.ts` 的真实命令。不要改命令名称、参数、返回结构或数据库；不要把现有作品、来源、个人记录与播放进度替换为静态数组，也不要用假成功代替保存、扫描或候选确认。

Windows页面、全局样式、Rust / Kotlin / SQLite迁移、Android工程与播放器内核由Codex维护。若某个前端需求确实需要改这些内容，输出清楚的接口 / 数据 / 原生能力需求，先与Codex对齐边界，不自行重写。

## 我希望的协作方式

1. 先沿用我已经确认的OpenDesign安卓视觉与交互规范，不自行推翻整体风格。
2. 每轮只实现我指定的一组页面或修改点，尽快让我看见结果、提出反馈；不要攒完整套页面后才交付。
3. 能访问共享工作树时，修改预览服务实际读取的这份React代码；保持当前数据、授权和个人记录。Codex与OpenDesign不要同时改同一文件，发现重叠修改先核对归属，不覆盖其他未提交工作。
4. 新功能已有后端接口时，接入真实接口并检查结果。没有后端时，说明需要哪些字段、命令、事件和状态，把需求交给Codex实现；相应入口明确标注待接入，不能模拟已完成。
5. 来源页应覆盖扫描进度、候选确认、连接失败、来源离线、权限拒绝和重试；播放入口应展示可恢复的错误。来源离线不删除索引或个人记录。
6. 安卓首版重点是动漫、电影、电视剧等视频。WebDAV属于首版目标，当前待接入；网盘经WebDAV服务接入与网盘账号/API直连要区分，直连具体网盘需我另行确认。漫画、轻小说和探索保留Future扩展位置。
7. 播放器设计可以继续交付区域、Token、状态和交互规范，但真实视频面与控件由原生Activity承载，交给Codex实现。React热更新不等于原生播放器控件也已更新，不能用React视频占位替代LibVLC。

## 实时预览与验收

- 使用电脑上的 `Genzo_Pixel9_API36 / emulator-5554`，构建变体为 `x86_64Debug`。暂不操作实物手机，不清除模拟器数据。
- 模拟器、SDK、工具和新增缓存放D盘，代码留在上述H盘工作树。
- 与Codex核对实时预览环境：由Codex搭建和验收Tauri Android开发模式、Vite热更新及必要的ADB转发；不要自行使用Windows开发端口、改原生构建桥或修改全局Tauri配置。
- 热更新验收必须实际保存一处临时文字或颜色修改，观察模拟器里的App自动变化，再恢复该临时修改；确认作品数据、目录授权和个人记录仍可读取。仅开发服务器启动、浏览器预览成功或APK编译成功，不代表模拟器热更新已通过。
- 热更新尚未就绪时，仍可推进页面设计与React修改，并提供本轮文件 / 补丁给Codex，通过重建安装验证。交接中准确写明当前预览方式与未验证项目。
- 每轮检查空态、缺图、长标题、键盘遮挡、系统返回和深浅主题，检查模拟器常用竖屏与横屏布局，保留Windows布局。
- 使用测试视频、真实用户授权资料或自有占位；来源和授权未确认的角色素材不能纳入产品。
- 完成验证后按项目约定提交自己的独立改动，更新设计交接；不要纳入Codex或其他Agent尚未提交的工作。
