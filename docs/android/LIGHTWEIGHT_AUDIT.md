# Android 轻量化审计

只清理确认无用途的内容，保留 Windows 管理 / 刮削、LibVLC、Readium、有效缓存、许可文件和有引用的预览资源。开发工具和构建缓存不是应用运行依赖。

## 已清理

- Kotlin 阅读器接管后，React 正文页的八项旧 CSS 选择器没有组件引用，已经移除。
- WebDAV 假表单和开关被真正的同步面板替代，移除其组件状态、表单及三项无引用样式。Bangumi 账号同步的后续位置仍保留。
- QA 构建目录曾累积旧哈希 JS / CSS：35个文件、13,312,960字节。重新生成后为19个文件、2,755,322字节。构建脚本检查明确的生成目录后使用 Vite `--emptyOutDir`，避免旧资源继续进入后端嵌入资源。

## 构建优化

`scripts/build-reader-qa.ps1 -Target aarch64 -Optimize` 使用 Rust release / size优化、thin LTO、符号剥离、Android R8与资源收缩。仍是独立签名的调试测试包，不是正式发布。

| 对比对象 | APK字节数 | Rust .so字节数 |
| --- | ---: | ---: |
| 常规QA包（F987DE68） | 118,067,792 | 55,859,960 |
| 经JNI修复的压缩QA包（364831F6） | 78,952,265 | 约25,372,920 |

包体减少约33.1%。这个对比包含过期构建资源清理和编译优化，不能将全部减少量归因于删除源文件。最终包的哈希 / 安装记录见 AI_HANDOFF。

初次R8验证发现了Tauri / LibVLC的JNI方法 / 类被收缩：保留生成的Wry规则、TauriActivity.getPluginManager和LibVLC的JNI类后重建，再在实体机回归。不能只看构建成功就启用压缩。

## 保留的大项

- LibVLC .so为45,875,392字节，负责解码、音轨、字幕与直接播放。
- Rust .so包含来源、SQLite、扫描 / 刮削、缓存、原生桥和嵌入前端，通过编译优化减小。
- Readium排版 / 可访问性资源和有预览引用的演示图片，没有依据证明永远无用途。
- PC专用源码没有从共享后端删除；Android编译器优化不可达代码不改变PC功能。
