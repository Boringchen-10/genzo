# 阅读获取修复与网络设置

日期：2026-10-05。开发版增量，不更新 v0.5.0 安装包或发布标签。

## 已确认根因

用户报告《魔都精兵的奴隶》等漫画能显示目录，但获取失败，界面显示“发生未知错误”，其他分话也不能继续获取。

1. 真实 Windows Tauri IPC 完成图片传输后，在发布缓存时返回 `文件系统错误：拒绝访问。 (os error 5)`。清单文件写入、同步后仍持有句柄，导致 Windows 拒绝重命名包含该文件的暂存目录。新增 `generated_cache_is_published_and_readable_on_windows` 在修复前稳定失败；发布前显式关闭清单文件后通过。
2. Rust 的 AppError 序列化为字符串，`getErrorMessage` 仅识别 Error，丢失实际报错。现在保留原始错误字符串。
3. 前端用一个 busy 状态禁用所有分话，且通用“重试”仅刷新目录。现在每章卷独立处理和显示错误，失败项重试原操作，其他章卷可继续加入队列。

原先生成临时 CBZ/EPUB 与复用合成完整缓存的测试未覆盖真实 Windows 缓存发布，因此不能用原测试证明下载成功。

## 使用与能力

- 设置 → 阅读网络：两条线路、六个 HOT 详情节点，线路内连接失败 / HTTP 408、429、5xx 自动尝试下一节点，或固定指定节点。登录与业务拒绝不通过轮换节点绕过。
- 测速实际请求公开 API，使用表单中的代理设置，结果为包含服务处理时间的请求耗时，不冒充 ICMP 延迟。测速和选择后保存。
- 系统 / 直连 / 手动 HTTP、HTTPS 代理；启用 reqwest system-proxy 的 Windows 固定代理支持。手动代理不接收用户名密码；Windows PAC 自动配置未接入，可明确填写代理地址。
- COPY API 域名与请求版本可编辑、从来源填充、重置并保存。域名仅接受当前 COPY 域名家族。每天自动更新是启动时距上次检查超过 24 小时才检查，失败保留原值并记录尝试时间；不是后台永久调度器。
- 漫画图片并发 1–8（默认 4），小说插图并发 1–4（默认 2）。最多同时获取两章卷，按来源顺序写入；暂时的连接、断传、408 / 429 / 5xx 最多三次尝试，权限 / 非瞬时错误不重试。
- 失败不替换旧完整缓存，临时内容不作为可打开文件；失败行显示具体章卷 / 页面原因。

## 在线数据与待定阅读器

用户进一步说明希望无需先下载文件获得正文，但尚在考虑内置或外置阅读器。因此本轮提供独立在线 IPC / TypeScript API，不增加尚未确定的阅读器界面或在线阅读按钮。

- `get_book_online_content(kind,pathWord,entryId,group)`：核对来源目录归属与访问限制；漫画返回按来源顺序排列的当前图片地址，轻小说取得整卷 TXT、严格解码并按目录行号返回文本章节和插图地址。
- `get_book_online_image(url)`：使用相同网络设置按需取一张图片，以二进制 IPC 返回，校验域名 / 格式 / 大小，不写阅读缓存。
- 两个命令均不生成 CBZ / EPUB、不写 `reading-cache`、不修改阅读状态。图片地址仅作当前请求数据，不保存签名 URL。普通目录和作品元数据仍可使用既有 SQLite 缓存。
- 漫画可逐页传输。小说来源只提供整卷 TXT，按章节展示仍须把整卷文本取到内存；不把“不写下载文件”描述成“不传输正文”。
- 来源账号、登录域名切换、会员 / 锁定内容、评论下载未接入；这并非桌面技术做不到，而是当前实现仅有匿名内容和正文模型。自定义下载保存目录也未实现，缓存继续位于独立设备数据目录；既有缓存目录打开可用。

- `cargo test --manifest-path src-tauri/Cargo.toml --lib --locked --offline`。
- `pnpm preview --host 127.0.0.1 --port 4187` 后运行 `node scripts/check-book-content.mjs`。
- 原生：构建一个全新 reading-network-qa UUID 配置，CDP 9241，先核对 EXE 内包含该唯一 identifier，再运行 `node scripts/check-reading-network-native.mjs`；脚本要求空库、无阅读缓存。可用 `TAURI_CONFIG` 加 `cargo rustc --bin genzo -- -o <独立QA绝对路径>` 输出，避免正在运行的默认 genzo.exe 占用导致 CLI 最后复制失败。
