# Genzo

Genzo 是一个 Windows 优先、轻量化、本地优先的 ACGN 统一媒体库。v0.2 用于扫描和整理用户自己的本地动漫、漫画、小说、游戏及其他文件，并为动漫提供可确认的 Bangumi 元数据匹配。

本项目不提供盗版资源搜索或内置播放器。v0.4 支持访问、播放及缓存用户自行配置且有权访问的 WebDAV 文件。删除作品或本地扫描目录配置只会修改 SQLite 记录，不会删除、移动或修改原始媒体文件。

## 电影与电视剧识别（Unreleased）

作品卡片、首页和详情页现已区分动漫、电影、电视剧、漫画、小说与游戏。品类从现有已确认记录读取，无需重新扫描；未识别视频显示“未分类视频”。文件类型仍用于播放器/阅读器调度，独立的品类筛选入口后续补齐。

电影与电视剧的海报及横幅来自 TMDB，动漫封面以 Bangumi 为主，横幅可来自 TMDB 或 AniList 补源。TMDB 横幅现在请求原尺寸，海报墙采用平滑缩略图；已入库作品请到详情点一次 **刷新元数据**，以升级旧图片缓存，再返回首页或媒体库查看。下载失败会保留旧图，最终清晰度仍取决于来源原图；无需删除缓存或重建媒体库。

1. 在 **设置 → 本地设置 → 元数据来源** 中填写 TMDB **API Read Access Token** 并保存（不是 API Key）。获取方式见 [TMDB 官方说明](https://developer.themoviedb.org/docs/authentication-application)。
2. 扫描目录后进入 **媒体库 → 待整理**，在批量入口或识别弹窗选择“电影”或“电视剧”。可按文件名查找，也可手动搜索中英文片名。
3. 电视剧核对季度（`0` 为特别篇）和勾选文件，点击“预览关联”后确认。S02E03、1x02 和 `Season 2/02.mkv` 可解析；不标季的连续编号、复合集数需要手动核对，不按 12 集猜季。
4. 确认后后台补齐中文资料、海报与分集；资料尚未就绪或网络失败时可在详情中“刷新元数据”。同剧不同季分别保留，手动分集关联优先。TMDB 没有提供中文内容时不能保证所有资料均为中文。
5. 电影默认只勾选当前视频；同目录其他电影不会自动一起归档，可自行勾选同一电影的其他版本和字幕。文件仍通过已配置的外部播放器打开。

TMDB 识别需要桌面端。浏览器预览不执行真实影视刮削。动画仍使用 Bangumi；仅补源的动画 TMDB 记录不会转为真人影视作品。批量影视识别先生成候选，不自动确认。设置中的 TMDB Token 使用现有本机设置存储，不会发送到播放器或写入日志。

影视功能复用现有数据库结构，不迁移、改名或修改真实媒体文件。没有可用分集时保留文件列表；刷新失败或空响应不会清除旧分集和手动关联。

This product uses the TMDB API but is not endorsed or certified by TMDB.

## 扫描任务与增量扫描（Unreleased）

在 **媒体库 → 媒体源** 启动扫描后，任务面板显示排队、当前目录、待处理目录和发现 / 已处理 / 复用数量。文件扫描与索引写入分开显示；作品识别在待整理执行，图片按需加载。离开页面后扫描继续，返回即可查看。任务保留最近 50 次摘要，较早任务可展开查看。

- **取消扫描** 放弃本轮索引提交，保留之前的记录与关联；索引开始提交后等待原子完成。网络挂载的底层 Windows 调用可能需要等待系统返回，但不会继续遍历剩余目录。
- **重试失败目录** 仅遍历这次失败的目录，不清理整来源的旧文件。来源地址、目录、类型或挂载模式改变后，请重新完整扫描。WebDAV 某个子目录失败仍会记录其他已发现文件。
- 重复扫描仍需枚举目录发现新增 / 移动文件；大小及可信修改时间未变时复用解析、指纹和索引。WebDAV 有可靠 ETag 时可复用无修改时间的记录，版本变化会重新处理；挂载和 WebDAV 不为扫描读取视频内容。
- 完整扫描成功才判定旧文件缺失；取消、超时及部分扫描不清理旧索引。应用异常退出留下的任务显示“扫描中断”，请重新扫描，不将它显示成已完成。

需重启更新后的 Tauri 后端，自动应用任务摘要迁移 `0015`；不重建数据库或修改真实媒体文件。

## v0.4 远程存储使用方式

进入 **媒体库 → 媒体源 → 添加 WebDAV**，填写服务地址、账号和应用密码，点击“连接并选择文件夹”，从根目录逐级点击文件夹；通过顶部路径或“返回上一级”切换位置，确认底部“待扫描文件夹”后点击“确认扫描此文件夹”。扫描包含该文件夹及所有子文件夹。扫描结果出现在“待整理”，继续使用现有识别、匹配与作品详情流程。

- Alist 可填写其 WebDAV 服务地址（例如 `http://127.0.0.1:5244/dav/`，以实际配置为准），无需手动填写目录；需要直接跳转时可展开“高级：直接输入目录”，路径相对于服务地址，打开成功后再确认扫描。这不需要 RaiDrive，也不是直接登录夸克。
- 已通过 RaiDrive、rclone 或 Windows 映射的目录，仍用“添加目录”，勾选“系统挂载目录”；已有来源也可切换此选项。
- 已配置的 mpv、VLC、PotPlayer 或 MPC 系列播放器，在服务器支持 Range 时通过本机转发直接播放。系统默认打开或其他工具先缓存；直接播放出现播放器兼容问题时，可手动点击“缓存”后再打开。
- “缓存”用于临时文件；“保留离线”把文件下载至应用数据目录的 `remote-cache` 并排除自动清理。媒体源页显示传输大小、重试、打开缓存目录和清理操作。两者均计入容量上限（默认 20 GiB）。
- 自动清理优先删除最久未使用的临时缓存；最近交给播放器的缓存保护 12 小时，避免使用中被删除。应用重启后解除这段临时保护。没有足够可清理空间时提示调整容量。
- 网络中断后可重试。服务提供可靠 ETag 或 Last-Modified 且支持 Range/If-Range 时续传，否则重新下载。远程暂时不可用不会清空媒体库，完整缓存可离线打开。
- 密码保存在 Windows 凭据管理器，不出现在数据库和播放器参数中。停用 WebDAV 来源保留索引和缓存；凭据失效时可通过“更新凭据”重新验证保存。

首版使用标准 WebDAV 的 Basic 认证与 UTF-8 XML 目录响应，建议 HTTPS。目录浏览不自动跟随重定向，需要填写最终服务地址。原生 SMB、各网盘专有登录、远程游戏执行、跨设备同步不在本版范围。外挂字幕可扫描关联，当前远程播放不自动转发外挂字幕，可下载后由播放器手动加载。

验证使用隔离的本机 WebDAV 服务与临时数据库，覆盖扫描、断线、Range 转发、缓存回退、续传、容量保护及三种 Windows 窗口尺寸；真实 Alist/网盘服务兼容性仍需用用户配置验收。当前版本为 0.4.4，包含 SQLite 并发写入、挂载缩略图、已有作品关联及探索/识别性能修复。

v0.4.4 修复大型本地/挂载目录扫描超过 5 分钟后丢弃本轮结果的问题，改为逐目录扫描，持续有进展时继续执行。当前目录连续 30 秒无响应会记录具体路径并继续其他子目录，保留已发现文件及旧索引；若 4 个系统读取仍阻塞则暂停剩余目录，待连接恢复后重试。UNC 与 Windows 网络盘自动跳过视频指纹读取；被挂载软件模拟为本地固定磁盘的来源仍请勾选“系统挂载目录”。

v0.4.3 修复倒序集数区间（如 `24-01`）触发数据库约束并中断整个目录扫描的问题。这类文件正常入库，集数留待手动关联。升级后重新扫描失败的媒体源即可，不必删除媒体源或重建库。

v0.4.2 探索页先展示本地索引与缓存，日历及补充资料后台更新；全量作品每次显示 48 项，可继续加载。待整理先对本地候选评分，只获取已选中作品的详情；季数明确的第二季和类型一致的独立 OAD/OVA 可自动匹配，信息冲突和 NCOP/NCED 仍需确认。升级后可对“待整理”重新识别，无需重新扫描或重建库。首次确认时的详情和封面仍受网络与服务限速影响。

v0.4.1 中作品详情读取不再执行数据库清理，旧路径记录在重新扫描或确认识别时合并。多步写入先排队再获取写锁；持续占用会提示稍后重试。升级沿用现有媒体库，无需重新建库。

### 文件移动后的恢复与媒体库检查

进入媒体库的 **媒体库检查 / 路径恢复**。异常检查只读取最近扫描索引，不探测所有磁盘或网络文件：来源不可用单独显示，可扫描 / 重连；失效路径、疑似重复、未关联分集和明确季数混放提供核对入口。重复依据文件名、大小和类型，只是提示，不能据此删除；每类最多显示 200 项。

移动文件后先保留旧作品和来源，在媒体源中添加并成功扫描新位置，让目标文件保持未归档。在“路径恢复”选择旧 / 新媒体源；单文件模式选择具体文件，文件夹模式选择已索引的子目录并按相对路径查找候选。核对新旧路径、勾选项目并确认是同一文件后提交，每批最多 1000 个。确认只合并索引，保留原媒体 ID、作品、分集、字幕、已有缩略图和观看进度，不改变真实媒体；旧来源配置保留，可在验收后自行停用。

文件类型 / 大小不符、已知指纹不符、目标已有归档 / 候选 / 映射 / 进度、源或目标有远程缓存、相关来源在扫描、文件在播放或预览过期时拒绝覆盖；失败整批回滚。目录内无唯一目标的文件保留，可单独定位；目录批量只处理已归档或缺失的旧记录。WebDAV、挂载与本地来源都使用同一确认流程，WebDAV 名称保留大小写。源列表超 10000 个文件时需缩小媒体源；已有远程缓存的资源迁移暂不支持，不会为迁移清除缓存。远程播放保护未解除时，结束播放、关闭播放器并重启 Genzo 后再尝试。

## v0.2 功能

- 多扫描目录、目录类型、启停、重复扫描、错误记录与缺失标记。
- 待整理内容按扫描根目录下的作品文件夹聚合，嵌套季目录不会展开成大量独立行；每次最多渲染 100 项。
- 删除目录配置后重新添加同一路径会复用已有媒体记录，不重复导入，也不会触发路径唯一约束错误。
- 作品和本地文件分离，支持手动创建、编辑、标签、状态、收藏、评分、备注和本地封面缓存。
- 海报网格与列表视图，支持标题搜索、类型/收藏/标签筛选及排序。
- 外部工具检测与自定义配置，支持 `{file}`、`{folder}`、`{title}` 参数模板。
- 默认工具、临时指定工具、Windows 默认程序和游戏启动项。
- 浅色、深色及跟随系统主题。
- 作品文件夹级动漫识别：优先从代表文件提取标题，纯集数文件回退到上层作品目录，并按作品组请求 Bangumi。
- 视频集数与外挂字幕关联，支持视频和字幕分别存放在同一作品目录的不同子目录。
- 可解释置信度：80% 以上且无歧义才自动匹配，60% 至 80% 等待确认，低于 60% 保持未匹配。
- 内置 `bangumi-data 0.3.132` 中/日/英标题索引、全年动画分页和周一至周日放送时间表。
- Bangumi 主源锚定；TMDB 可补全高清海报/背景图，AniList 可补全国际评分和标签，补源均须通过 85% 标题与年份校验。
- 搜索与聚合采用 100 项内存 LRU + SQLite 持久缓存；保存作品时同步缓存 Bangumi 分集标题。

联网元数据不可用时，扫描、手动整理、媒体库浏览和外部工具启动仍可正常工作。v0.2 只支持动漫元数据；漫画、小说和游戏 Provider 留待后续版本。豆瓣因没有适合本应用的稳定授权公开 API，目前明确显示为不可用，不抓取网页。

界面使用“动漫”作为视频类媒体名称；数据库和 Tauri command 中继续使用稳定的兼容键 `video`，不会因此迁移或覆盖已有数据。

## 技术栈

Tauri 2、React、TypeScript、Vite、Rust、SQLite、SQLx、Zustand、React Router、Tailwind CSS 和 Lucide。

前端不直接访问数据库或文件系统。数据库、扫描、封面缓存及进程启动均由 Tauri commands 完成；目录选择使用 Tauri 官方对话框插件。

## 开发环境

- Windows 10 或 Windows 11
- Node.js 22 或更高版本
- pnpm 11
- Rust stable MSVC 工具链
- Visual Studio 2022 Build Tools，包含“使用 C++ 的桌面开发”和 Windows SDK
- Microsoft Edge WebView2 Runtime

安装依赖并启动：

```powershell
pnpm install
pnpm tauri dev
```

本仓库不会启动独立 HTTP 后端。开发时 Vite 仅为 WebView 提供前端热更新；应用数据和所有系统操作仍在本地 Tauri 进程内。

## 构建

### PotPlayer 观看记录（Unreleased）

在「工具」中配置已安装的 `PotPlayerMini64.exe` / `PotPlayerMini.exe`，并设为视频默认工具，或从详情页的文件菜单选择该工具。**系统默认打开不采集进度**，即使系统默认播放器也是 PotPlayer。

从 Genzo 打开视频后，首页和作品详情的「观看记录」显示保存的位置，可选择「继续观看」或「从头播放」。播放期间保持 Genzo 运行；约每 5 秒保存一次，正常关闭播放器时补存最后一次有效采样。异常退出最多可能损失最近几秒，不能恢复安装本功能前的观看历史。

首版使用独立 PotPlayer 窗口核对文件，重复打开同一文件需先关闭其播放窗口。播放器内换集会停止原文件记录，请从 Genzo 打开下一集。其他播放器仍可打开文件，但没有自动进度。接近片尾的文件显示「已接近片尾」，不自动改变作品收藏状态，也不意味着整季看完。

WebDAV 沿用既有本地代理/缓存打开流程；在线续播仍取决于服务的 Range/拖动支持。RaiDrive/UNC 路径仅在启动和会话比较时规范化，数据库保留原路径。无法核对文件、读取位置或跳转时保留旧进度并显示提示。

前端对接与测试说明见 [docs/PLAYBACK.md](docs/PLAYBACK.md)。

生成 Windows 可执行文件但不打包安装器：

```powershell
pnpm tauri build --no-bundle
```

产物位于 `src-tauri/target/release/genzo.exe`。v0.2 暂不包含自动更新或第三方工具安装器。

## 本地数据

默认数据目录：`%APPDATA%\com.genzo.desktop`

- 数据库：`genzo.db`
- 封面缓存：`covers\`
- WebView 运行数据由 WebView2 存放在对应本地应用数据目录

SQLite 采用迁移和 WAL 模式。初始化或迁移失败会中止启动并返回明确错误，不会静默重建数据库。

Bangumi 搜索结果缓存 7 天，作品详情与多源聚合缓存 30 天。封面只接受 Bangumi、TMDB 与 AniList 的受信任 HTTPS 图片域名，解码验证后写入本地缓存，并生成缩略图；API 失败不会阻断本地扫描。

TMDB 是可选补源，需要 Read Access Token。当前设置界面尚未由 Open Design 接入该字段时，可在启动 Genzo 的终端中临时设置环境变量：

```powershell
$env:TMDB_READ_TOKEN='你的 TMDB Read Access Token'
pnpm tauri dev
```

也可以通过既有 `set_setting` 契约保存键 `metadata.tmdb_read_token`。Token 不随媒体库数据发送给 Bangumi、AniList 或豆瓣。

## 版本管理

项目使用 Git、Conventional Commits 和 Semantic Versioning 管理变更。功能更新与 Bug 修复在验证后形成独立提交；正式发布同步更新前端、Tauri 和 Rust 包版本，维护 [CHANGELOG.md](CHANGELOG.md)，并创建 `vX.Y.Z` 标签。

完整提交与发布流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

### 待整理：批量预览与撤销（Unreleased）

- 进入待整理，可针对当前目录及子目录连续处理，或打开「批量预览与确认」。每批最多 50 个季度 / 特别篇组；查找候选时不改变文件归属。
- 核对目标作品、季数和文件范围后勾选，可统一确认；每组独立保存，失败留在弹窗供重试，成功组不会重复提交。连续处理可跳过，确认后留在当前目录刷新。
- 单项识别和「关联已有作品」均可按季度、NCOP / NCED、OVA / OAD 等分组勾选。没有季度标记的连续编号仍须手动核对，不按固定 12 集自动拆分。
- 「识别记录」保留最近 50 次关联，可二次确认撤销。撤销恢复作品资料和分集关联，不移动文件，也不清除播放进度；相关资料、文件或分集有后续更改时会拒绝覆盖。较早的记录需先撤销后来作用于同一作品的操作。
- 既有历史关联不会凭空补生成可撤销记录；此功能需重新启动更新后的 Tauri 后端。浏览器演示不提供真实撤销。

作品详情页的「识别记录」只展示关联到当前作品 ID 的记录，同名作品不混在一起；待整理页仍展示全库记录。保留策略仍为全库最近 50 次，不会因增加作品筛选而恢复已清理的旧记录。

识别记录默认显示最近 7 天，可切换最近 24 小时、30 天或全部保留记录。筛选依据是确认识别时间（过去连续时长），不是文件日期、作品添加时间或撤销时间；按本机日期分组并显示到秒。时间范围内没有记录时可切换更长范围；已被 50 条保留策略清理的记录不会重新出现。
